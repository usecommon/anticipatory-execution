# Authored directory measurement challenges — v0.1

This is a separate engineering challenge set, not sampled public data, a synthetic efficacy benchmark or research annotation. The accepted next step is to test distinctions absent from the original public cases. Preserve those public cases, eight earlier static-oracle witnesses, labels, split and frozen thesis unchanged.

Freeze the authored cases and expected mechanical outcomes before running. Cases deliberately vary final target, hidden-entry requirements, listing dependencies, receipt integrity, provider metadata and executor behavior. They do not estimate prevalence or speculation risk. Repeated variants are dependent and no significance interval is warranted.

Use an explicit mocked directory provider with (directory identity, incarnation, listing revision) metadata. A listing request returns names, hidden-coverage flag and integrity digest. The simulated final provider exposes only the requested directory metadata to the guarded reuse decision; full final entry sets remain in the independent evaluator/fresh-listing path. Every metadata request and enumeration is counted separately. Hashing a receipt establishes byte integrity, not authenticity. The mocked revision service is NOT a feature of the pinned BFCL API and has not been deployed or benchmarked.

Receipt acceptance requires target identity, incarnation, revision, request coverage and byte integrity. If accepted, filter broad hidden-inclusive results for a visible-only final task. Otherwise use fresh enumeration, or report unresolved if the environment is unavailable. An explicit ignore mode may choose not to reuse an admissible receipt. A read-irrelevant mode may read rejected data without treating it as a contribution. Keep admissibility, actual consumption, verified contribution, final correctness and offline reuse witness separate; never compute research binary/fractional labels from them.

The independent task check computes the required target/name set from authored final requirements and environment, separately from the candidate and policy's metadata view. Broken-provider cases intentionally leave revision unchanged while required names change: the guard may accept stale output, and the independent checker MUST expose the task failure. Count an expected failure detection as a challenge-check pass, not as correct task execution. This tests a contract assumption, not a claim that revision metadata always works.

Incarnation prevents same-name/revision ABA replacement. Listing revisions cover names/types/visibility dependencies; unrelated directories and file-content-only changes need not invalidate a names-only listing. Missing metadata is not proof of invalidation: guarded refusal is conservative and must not imply a negative usefulness label. Missing environment facts remain unresolved.

All actions are in-memory typed operations. No shell, host directory enumeration, network, external mutation, models, probes or human labeling. Record costs as symbolic metadata/ls calls, excluding simulator/oracle overhead explicitly. Do not claim a speedup. Parameterized drafts/generic preparation still need rubric alignment beyond this directory domain. No confirmatory extraction.
