# Annotator C methods

These are independently authored AI-generated annotations, not human-rater judgments. The only study input files read were `C/RUBRIC.txt` and `C/items.jsonl` in this assignment directory. No repository materials, other raters' submissions, owner keys, private mappings, or prior results were inspected. No candidate actions were executed and no browsing was performed.

I considered each record's prefix and candidate action before comparing it with its full instruction. I authored all 200 judgments and item-specific rationales explicitly in `judgments.txt`. Python standard-library code parsed those authored judgments into `submission.jsonl` and checked the count, exact ID coverage, uniqueness, numeric bounds, flags, and nonempty rationales. The code did not infer labels from keywords, IDs, ordering, or a default rule.

The first input display was truncated. I recovered the missing middle records using compact displays of their prefix, action, arguments, and full instruction. This display adjustment was the only procedural deviation; those compact displays omitted auxiliary domain and execution-class fields. No adjudication was performed.

Limitations: the rubric's material-reexecution threshold leaves uncertainty for generic drafts, broad retrievals, and partially overlapping target changes. Actual candidate outputs and result coverage were unavailable. I marked genuine uncertainty rather than assuming hidden preferences or a particular generated output. Fractional utilities are qualitative survival estimates, not measured performance. These AI annotations alone cannot establish human reliability or a G1 pass.
